```tsx
const [view, setView] = useState<DataTableView>("table");

<DataTable.Root
	columns={columns}
	data={organizations}
	view={view}
	renderGalleryCard={(organization) => (
		<DataTable.GalleryCard
			src={organization.logo}
			name={organization.name}
			activity={organization.activity}
		/>
	)}
	toolbar={
		<DataTable.Toolbar>
			<DataTable.Actions>
				<DataTable.ViewToggle view={view} onViewChange={setView} />
			</DataTable.Actions>
		</DataTable.Toolbar>
	}
/>;
```

`view="gallery"` swaps the table for a card grid built from the same sorted,
filtered row model, so the toolbar's [search](/ui-datatable/global-filter) and
filters keep working unchanged. The grid shows every row at once and never
renders the `pagination` footer — a directory people browse, not page through.
With server-side pagination, fetch the full result set before switching.

Cards stay clickable through `onRowClick`, and the columns still exist
underneath — sorting set in table view carries over.

## API

### DataTable.ViewToggle

<PropTable of="DataTable.ViewToggle" />

The table ⇄ gallery switch, at home in `DataTable.Actions`. It holds no state:
pass `view` back to `DataTable.Root`.

### DataTable.GalleryCard

<PropTable of="DataTable.GalleryCard" />

The directory-entry anatomy — logo large on top, name below, activity last —
to return from `renderGalleryCard`. Without a logo it falls back to the name's
first letter. Any other card content works too; the prop takes arbitrary JSX.
